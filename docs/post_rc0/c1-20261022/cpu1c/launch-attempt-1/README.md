# cpu1c launch attempt 1: stopped before the chain started (operational wrapper defect)

At 22:18:44Z the one-shot operational wrapper (`../freeze/cpu1c-launch-wrapper.sh`) stopped before starting the chain. It had set `noclobber`, so `exec 9>"$LOCK"` could not open the lease file that the pre-launch probe had just created ("cannot overwrite existing file");
`flock -n 9` then reported a bad descriptor and the wrapper wrote `lease.contended`, which was a misnomer: the lease had no holder. Nothing else happened: the gate `logs/chain-cpu1c.go` was never created, the chain never ran, no `cpu1c-*` stage receipts exist and no process was left running.
Per the stop rule there was no retry. The frozen chain, tools, inputs, pins, binaries and source are unchanged. A corrected wrapper (`../freeze/cpu1c-launch-wrapper2.sh`: lock opened without noclobber, a new launch directory `cpu1c-launch2`) was self-tested harmlessly on temporary files (existing lock file works, a second instance reports contention without starting a chain, the chain exit code 5 is preserved, affinity 8-9 recorded, lease free again afterwards) and is deployed but has not been run. This directory holds the receipts of the stopped attempt unchanged.
