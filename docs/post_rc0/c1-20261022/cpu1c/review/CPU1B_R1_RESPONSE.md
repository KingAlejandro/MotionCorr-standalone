Review report retained verbatim as `CPU1B_R1_REVIEW.md` (sha256 `14517c28e5bbeeea7f66f7e25e8c57f8d94490cfe56c32b1b6577c791e31ed3b`). The parent's negative control is retained in `../parent-control/` (`CONTROL.json`, `c1.json`, `F.json`, `published.json`, `result.json`).

**Parent finding (not caught by the review): false K267 PASS.** With all eight C1 and F rows at native exit 0, `dc` unset, checker exit 2, status `ABORT_NO_RESULT`, null field metrics and field gate `ABORT`, the cpu1b `v2check` returned PASS because the two arms were equal. Fixed in `cpu1c_sums.py`: every row must carry complete, finite, non-negative `rms`/`p95`/`max` dictionaries for `field_px` and `field_angstrom`, an integer native exit 0 (not a bool, float or string), `field_gate` PASS or FAIL, and a checker outcome that follows the checker's own contract
(`tools/check_motion_diagnostics.py`): `UNIDENTIFIABLE` only for `flat` and `repeated`, otherwise PASS or FAIL matching the field gate; `sampling_status` VALID or OUTSIDE_FIXED_ROI; checker exit 1 exactly when sampling is outside the fixed ROI or a gate-role case (`zero`, `integer`, `fractional`, `affine`, `pedestal`) fails, else 0; PASS never with a sampling problem; exit 2 and `ABORT_NO_RESULT` are rejected as "no report". This is the exact checker contract rather than the shorter "FAIL gives 1, PASS/UNIDENTIFIABLE gives 0" rule, because a characterization case (`noisy`) can legitimately exit 0 with FAIL and an unidentifiable case outside the ROI exits 1; no legitimate FAIL or UNIDENTIFIABLE outcome is rejected and no case is required to PASS. Equal-but-invalid rows now give exit 2 (invalid); a genuine C1-vs-F difference gives 1. The control reproduces PASS on the old helper and exit 2 on the new one (`test_parent_actual_control_files_discriminate_old_from_new`).
