## 3. Technical Challenge of Alias, Normalization, and Control Mechanics

1. **Can directory aliases conceal broken product or source validation?**
   - **No.** In `c1-i4-L.sh`, `ln -s "$SC/t24-i3/$a-L" "$T/$a-L"` links the parent arm directory. Inside `compare_output_trees.py::validate_tree`, `root = root.resolve()` resolves `$T/<arm>-L/out` to `/mnt/clathrin/.../t24-i3/<arm>-L/out` before checking the 24 MRC and 25 STAR files.
   - The symlink prohibition `if (root / rel).is_symlink(): raise ValidationError(...)` checks individual product files (`Movies/*.mrc`, `Movies/*.star`, `corrected_micrographs.star`), which remain regular files inside the resolved `out/` directory.
   - `_path_inside_root` resolves both the STAR entry (`p.resolve(strict=False)`) and `root.resolve()`. For imported arms, the STAR entries contain `/mnt/clathrin/.../t24-i3/<arm>-L/out/Movies/...`, which resolves inside `root.resolve()` (`.../t24-i3/<arm>-L/out`). No validation check is bypassed or weakened.

2. **Comparator & `lane_hash` output-root normalization across `t24-i3` and `t24-i4-20261025`:**
   - **In `compare_output_trees.py`:** `compare_trees` sets `b_root, c_root = base.absolute(), candidate.absolute()` (`.../t24-i4-20261025/<arm>-L/out`) and `_normalise_text` replaces both `str(root)` and `str(root.resolve())` (`.../t24-i3/<arm>-L/out`) with `<OUTROOT>`. Thus, comparing an imported arm (whose STAR files contain `t24-i3` paths) against a newly run arm in `t24-i4-20261025` (whose STAR files contain `t24-i4-20261025` paths) normalizes both to `<OUTROOT>` cleanly without false diffs or masked path corruption.
   - **In `c1_tutorial24.py::lane_hash`:** `_norm_star(b, fresh_tree)` replaces both `str(fresh_tree)` (`.../t24-i4-20261025/F-fresh-L/out`) and `str(Path(fresh_tree).resolve())` (`.../t24-i3/F-fresh-L/out`) with `<OUTROOT>`.
