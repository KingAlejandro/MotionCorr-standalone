## New findings
**M1 (MATERIAL; pre-launch disposition) — the required thread/mask sampling of the child is not recorded.** Approved `PLAN.md:23` requires: "Record actual process/thread/mask sampling; --j2 does not prove total Threads==2 (earlier 3-thread deviation remains known)". `driver_v5.launch` (`driver_v5.py:142-171`) sets affinity in `preexec_fn` and waits. It never reads the child's `/proc/<pid>/status` (Threads, Cpus_allowed_list) or task count. `real_guard` reads only the driver's own mask (`:83`). V5_PLAN §4 dropped the requirement, and the README lists no deviation. Under the no-retry protocol this receipt cannot be produced after the runs. Fix: poll `/proc/<pid>/status` and `/proc/<pid>/task` every ~0.1-0.25 s inside the wait loop, and record max/observed Threads and masks in RUN.json as an extra key. `admit_producer` reads named keys only, so an extra key is admissible. Make it a record, not a new STOP criterion, unless the parent decides otherwise. The alternative is an explicit parent waiver. This is not an output-correctness defect: the CPU build has been bit-identical across thread counts in earlier evidence.

**L-A (LOW) — the lease probe proves "someone holds the current inode", not that our lane holds it** (`driver_v5.py:71-82`). The check is an env-string set equality plus an LOCK_NB probe on the path. A peer can delete and recreate a lock file that lane.py holds (a known incident pattern on this box). Lane then holds the orphaned inode, the peer holds the new one, and the probe is refused, so the guard reports the lease as held. Probe result: control_unheld gives STOP; control_lane passes; split_inode **passes**, with the path inode equal to the peer's (`results/probe_split_inode_lease.log`). Backstop: heavy foreign work on 32-47 (>1.5 busy cores) still stops at the next guard. A light or off-range peer overlaps our 2-thread runs undetected. Our results are unaffected; the peer's timing is not. Fix (~6 lines): require `os.stat(p).st_ino` to appear in `/proc/locks` as a FLOCK WRITE held by `os.getppid()` (lane.py; taskset execs), or have lane export (dev, ino) and compare. Until then, describe the receipt as "held by some process".

**L-B (LOW) — scratch and free-space admission is partly static** (`:92-95`). `prior_scratch_bytes` is the frozen 6,041,466,254 B (the four prior namespaces at freeze) and is not re-measured per step. There is no per-step free-space check, although PLAN.md:23 says "sufficient free space". lane.py's start-of-run `df -h /tmp` is the only free-space receipt.

**L-C (LOW) — failure paths outside the caught exception types.** `run_campaign` logs STOP only for DriverStop/PairError/AdmissionError (`:232`). A Popen OSError, KeyboardInterrupt or other exception still stops everything, but the ledger has no STOP record: a `launching` event appears without `finished`, and there is no RUN.json. The child runs with `start_new_session=True`. If the driver or lane dies (for example SSH hangup), the child keeps running with no timeout after the leases are released. The guard samples only before each launch, never during the child. All of this is acceptable for short correctness runs; state it as a limitation.

**L-D (LOW, documentation precision).** `check_release` only format-checks `delta_review_report_sha256` and `approved_by=='parent'` (`:184`). V5_PLAN §4 says the hashes are "each equal to the files in use", but the driver cannot see the report. The parent's release index is the actual binding. PARENT_RELEASE does not bind the tests file or the fresh resource admission, while COMMANDS is bound transitively through the module anchor. Shared libraries are pinned in the admission but not re-hashed on disk before launch; a changed library would most likely fail closed at OFF identity (inferred). `controlled_environment_observed` is the dict passed to Popen, not read from the child. It is still the actual environment, because nothing is inherited.

## Resource guard vs approved protocol (requested assessment)
- Fresh allocation per producer: yes. `guard()` runs before every launch (`:215`) and checks the held-set equality against a freshly computed overlapping set (a new overlapping lock stops the campaign), plus a flock probe, an allowed-CPUs check (32-47 exactly), busy cores on 32-47 ≤ 1.5 over 2 s, MemAvailable ≥ 8 GiB, and combined scratch ≤ 25 GiB. Each guard receipt is retained and hashed into RUN.json.
- No foreign heavy overlap: honoured for CPUs 32-47 at launch instants. The metric counts all busy time on 32-47, including our own, so it is conservative. It uses the same formula and 1.5 threshold as the build-time `occ()`. It is blind to work on other CPUs and to anything that starts mid-run; for correctness runs that is acceptable.
- Matching real held leases: only partly; see L-A. The guard does more than trust the env string, but it does not establish ownership.
- Thread/mask recording: absent; see M1.
- No new broader criterion is introduced. The M1 and L-A fixes are a record and an ownership check respectively, and the parent decides whether either is adopted.

## Correctness of the producer flow (fake child only)
For each case in the frozen order (noisy, affine, pedestal, zero, integer, fractional, flat, repeated) the driver does the following. It runs the guard and then the identity check. It creates a fresh exclusive `evidence/<case>/<arm>` and stages exactly `<case>.star` and `<case>.mrcs` at their pins (truth is never staged). It appends to the ledger, then launches once with argv/cwd/env exactly from the resolved row plus `PATH=/usr/bin:/bin`, combined stdout+stderr, affinity 32-47 and a wall limit. A RUN.json is written from what actually happened. A non-zero exit or timeout stops the campaign. OFF then goes through `pre_ON_gate` (admission, baseline, OFF raw identity, manipulation, comparator) and ON through `admit_single`. After 16 launches, `decide_pilot` runs once. Truth-gate FAILs are recorded in DECISION.json and remove no row. The flat and repeated cases are reported as UNIDENTIFIABLE. Typed v3 `on_launch_permitted` is unused. The budget ceiling is 16. A pre-existing ledger, or a non-empty evidence root, is refused. The dry run creates nothing. The child environment carries no inherited MC_/GPU knobs, and the CUDA-OFF binary has no `--gpu`.
