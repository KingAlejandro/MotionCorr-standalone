# Clarifications to the executed 4GPUs timing records (added 2026-10-18, after review R-D11 round 3)

The files in this directory are kept byte-identical to what ran. These notes correct two statements in them; they change no measured value and no D14 label.

1. **`rule.txt` line 19, null placement (P3-a).** `rule.txt` says the last null block follows the last comparison block. The implementation (`wd11_pairs.fixed.py:168`) puts a null block after every k-th comparison block, with k = N/2 // 8 by integer division, and stops after 8 null blocks. That holds only when N/2 is a multiple of 8. tutG and tutL (N = 128) satisfy it. **e10216L (N = 72) does not:** k = 4, so the 8th and last null block came after comparison pair 64 (block 32 of 36), and comparison pairs 65–72 followed it (`e10216L/plan.json`). The 16 null pairs and the 72 balanced comparison pairs are all present and their values are unaffected; only the stated position of the last null block is wrong. The confirmatory draft (`../confirmatory-draft/`) places null blocks so that the last one follows the last comparison block for every N.

2. **`timing4b.sh` line 2, which nulls were defective (P3-b).** The comment says the interleaved nulls of tutG *and tutL* used the defective driver. Only **tutG** did. The fixed driver was installed at 02:02:41Z (`driver-change.txt`), and the tutL driver process started at 02:10:22Z, after a 559 s wait for the bench lock (`tutL/window.txt`). tutL's A′ CPU time matches A (10.31 vs 10.23 s), so its interleaved null is valid. The tutL replacement null (`tutL-null/`) was therefore unnecessary. It is kept and reported alongside, not used in place of the interleaved null. README §6 already reports this correctly.
