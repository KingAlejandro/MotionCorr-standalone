# Architectural Design Specification: #72 — Fail-closed CI and canonical fixture integrity

- **Issue Reference**: [#72](https://github.com/KingAlejandro/MotionCorr-standalone/issues/72) — Run required validation and CUDA compilation on stacked PRs
- **Track**: `track:validation`
- **Depends on**: #5 (Linux CI baseline), #59 (known-motion gates), #82 (CUDA compile-only CI separation), #89 (fixture manifest verification approach)
- **Coordinates with**: #96 (audit map), #97/#98/#99 (additive CMake test registrations)
- **Status**: Proposed / In Review
- **Scope**: CI failure policy, CMake test dependency enforcement, canonical fixture verification, and negative controls. **No numerical acceptance threshold is changed; no kernels are edited; no reference data is regenerated.**

---

## 1. Problem Statement

Audit of the current baseline (`4c952b3f54479653512c4d208e09c9a8c02f3726`) revealed key failure-policy vulnerabilities in CI and fixture validation:

1. **Silent truth-script skip in CI**:
   `.github/workflows/ci.yml` previously executed known-motion validation with:
   ```bash
   if [[ ! -f tools/run_known_motion_gates.py ]]; then
     echo "Known-motion suite is absent from this revision; PR #63 adds it."
     exit 0
   fi
   ```
   If a regression or branch removed or renamed `tools/run_known_motion_gates.py`, the required validation step exited 0 (green pass), silently bypassing all known-motion checks.

2. **Silent test omission in CMake**:
   In `CMakeLists.txt`, when `BUILD_TESTING=ON`, tests were guarded by:
   ```cmake
   find_package(Python3 COMPONENTS Interpreter)
   if(Python3_Interpreter_FOUND)
       add_test(...)
   endif()
   ```
   If Python 3 was absent or undetected, CMake silently omitted test registration with zero warnings or errors. Running `ctest` would result in 0 tests run, passing without executing any tests. Furthermore, if Python 3 was present but `numpy` was missing, configuration succeeded but runtime tests failed unpredictably rather than failing at configuration/preflight.

3. **Weak CTest collection validation**:
   CI validated test collection via:
   ```bash
   ctest --test-dir build --show-only | grep SyntheticRegression
   ```
   This only asserted that one string appeared in text output. It did not verify total test collection count, did not detect missing test suites, and did not guarantee that the complete suite was registered.

4. **Self-referential fixture generator overwrite**:
   `test-data/generate_known_motion_fixture.py` automatically rewrote `args.outdir / "MANIFEST.json"` upon generating fixtures with `--case all`. When fixtures were generated in an environment with divergent floating-point or NumPy behavior (e.g. NumPy 1.22 vs 2.x), the generator wrote a new manifest matching its own generated bytes. Any subsequent verification against the adjacent manifest resulted in a tautological pass ("verifying against itself"), hiding noncanonical fixture drift.

## 2. Objectives and Non-Objectives

### 2.1 Objectives
- **O1**: Enforce fail-closed execution in CI. Absence of any required truth or validation script (`tools/run_known_motion_gates.py`, `tools/test_compare_motioncorr.py`, etc.) must fail the CI job immediately with nonzero exit.
- **O2**: Enforce test dependency requirements when `BUILD_TESTING=ON`. CMake must require `Python3` and verify the availability of `numpy`. `BUILD_TESTING=OFF` must remain strictly independent of Python.
- **O3**: Validate CTest suite collection structure via machine-readable `ctest --show-only=json-v1`, failing if the test count is zero or any required test name is missing from the collection.
- **O4**: Enforce canonical fixture verification against the committed git manifest (`test-data/known_motion/MANIFEST.json`). Fixture generation must never overwrite the committed manifest unless an explicit maintenance flag (`--write-manifest`) is provided.
- **O5**: Provide comprehensive negative controls verifying that absent scripts, missing dependencies, empty test collections, missing fixtures, bit-flipped fixtures, and self-consistent noncanonical fixtures reliably fail their designated gates.

### 2.2 Non-Objectives
- No changes to numerical thresholds or physics tolerances.
- No editing of CUDA or C++ processing kernels.
- No regeneration or replacement of canonical reference outputs.
- No modification of GitHub Actions permissions or introduction of self-hosted runner credentials.

## 3. Architecture and Implementation Details

### 3.1 CI Workflow Fail-Closed Policy (`.github/workflows/ci.yml`)
1. Remove the fallback `exit 0` from the known-motion validation step. The script check asserts existence; failure to find `tools/run_known_motion_gates.py` or associated test scripts exits 1.
2. Add explicit canonical fixture preflight step verifying fixture integrity with `tools/verify_fixtures.py` prior to running numerical checks.
3. Validate CTest registration using `tools/validate_test_collection.py` reading `ctest --test-dir build --show-only=json-v1`.

### 3.2 CMake Test Dependency Enforcement (`CMakeLists.txt`)
When `BUILD_TESTING=ON`:
- Use `find_package(Python3 COMPONENTS Interpreter REQUIRED)` to guarantee Python availability.
- Execute an inline Python probe verifying `numpy` is importable. If missing, fail with a clear diagnostic message directing the user or CI to install required dependencies.
- Retain additive test registrations compatible with concurrent tasks (#97, #98, #99).
- When `BUILD_TESTING=OFF` (the default for production builds), no Python search or checks occur.

### 3.3 Fixture Generator & Verification (`tools/verify_fixtures.py`)
- `test-data/generate_known_motion_fixture.py`: Default execution generates `.mrcs` files without modifying `MANIFEST.json`. Only when `--write-manifest` is explicitly passed will `MANIFEST.json` be rewritten.
- `tools/verify_fixtures.py`:
  - Inspects `test-data/known_motion/MANIFEST.json` (reading from `git show HEAD:test-data/known_motion/MANIFEST.json` when in a git checkout, falling back to disk manifest when in a source archive).
  - Verifies exact SHA-256 digests and file sizes for all declared cases (`km_global_hisnr`, `km_local_hisnr`, `km_local_noisy`, `km_local_nonsquare`, and optional heavy cases).
  - Rejects missing fixtures, corrupted/mismatched fixtures, and undeclared extraneous fixtures.

### 3.4 Negative Controls Suite (`tools/test_ci_fail_closed.py`)
Executes fast, hermetic unit/integration negative controls in temporary sandboxes:
1. `test_absent_truth_script_fails_closed`: Verifies that invocation fails when a required validation script is missing.
2. `test_absent_dependency_fails_cmake`: Verifies that `BUILD_TESTING=ON` fails configuration if python/numpy is absent.
3. `test_empty_or_truncated_ctest_collection_fails`: Verifies that `tools/validate_test_collection.py` fails on empty or missing test names.
4. `test_missing_fixture_fails`: Verifies that `verify_fixtures.py` fails when a required fixture file is deleted.
5. `test_byte_flipped_fixture_fails`: Verifies that `verify_fixtures.py` fails when a single byte is mutated.
6. `test_noncanonical_regenerated_fixture_fails`: Verifies that a fixture generated with an altered parameter or local noncanonical seed fails verification against the committed manifest, even if an adjacent local manifest matches it.
