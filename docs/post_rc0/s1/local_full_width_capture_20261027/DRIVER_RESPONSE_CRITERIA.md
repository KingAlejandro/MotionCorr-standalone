## Mandatory
- **C1.** Immediately before every `Popen` the driver re-hashes the pinned binary and the staged `native-input` files (hashes, exact file set, regular files, no symlinks), and re-checks that the immutable pins (`RUN_PINS_v2.json` hash taken at start) and the staging sources (baseline input files) are unchanged. After every run the binary hash is recomputed and compared with the pin; the RUN receipt records both; a mismatch retains the run, writes `INVALID.json` in the run directory and a STOP. Negatives that must STOP: binary swapped between OFF and ON (before the ON launch), staged input swapped after OFF (before the ON launch), extra or symlinked staged file, changed pins file, binary changed during the run (retained invalid). No retry, no adaptation.
- **C2.** After the witnesses and coverage pass, the driver inventories every path under the capture directory (relative path, size, sha256; any symlink or non-regular entry is a STOP), cross-checks the file count against the independently derived expected total (session.json and COMPLETE.json plus, for each selected patch, the expected writer sequence for its executed iterations plus patch-files.json: 604 for two iterations), writes `capture-inventory.json` outside the capture tree, re-inventories and compares immediately before declaring completion, and binds the inventory sha256 and file count in `NATIVE_COMPLETE.json`. Truth and analysis stay UNRUN until the record is sealed.
