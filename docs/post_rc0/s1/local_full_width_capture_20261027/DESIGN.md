# Full-width two-patch same-state CCF capture: design note and frozen test criteria

Status: design frozen before source edits. Source change is a default-off diagnostic extension of the existing reviewed capture (`src/local_ccf_capture.h`, `MC_DIAG_LOCAL_CCF_DIR`). Native producers stay HELD; no job is released by this note.

## Purpose
After the full-width pilot, the noisy ON arm still shows accepted-patch observation errors (observation-residual diagnostic: largest at (104,15); the old bad patch (62,79) improved under full-width). The open question is whether the residual comes from the same-state objective basin, frame 0 / reference, or iteration, rather than the local fractional fit. That needs the actual native CCF state under full-width, not the old-weight capture and not a NumPy-regenerated movie. The existing capture refuses `--experimental_local_full_width_weight`, so none exists.

## Change (minimal, default off)
1. A diagnostic mode enum `LocalCcfDiagnostic::Mode { Legacy, FullWidthPair }`, passed to `LocalCcfCaptureSession` and then to each `LocalCcfCapture`. The runner derives it from the existing flag: `MC_DIAG_LOCAL_CCF_DIR` with `--experimental_local_full_width_weight` OFF gives `Legacy`; both ON gives `FullWidthPair`. There is no new CLI option, environment variable or general selection framework.
2. `Legacy` keeps the old selection (62,47),(62,79), directory names, file set and all bytes written (session.json, patch.json, fft-config.json and every array), unchanged.
3. `FullWidthPair` selects exactly (104,15) and (62,79) of the noisy 128x96x5 movie (patch extents [84,126)x[0,32) and [42,84)x[64,96), both 42x32). It records every item of the reviewed capture for all 5 frames and all actually executed iterations: initial and enter/exit FFTs, reference, window/sum-of-others/raw product, pre-DC, post-DC (API consumed), API-after, the actual C2R temporary before and after, the native float map, peak/verdict/unclipped shifts, stopping state, cumulative shifts, reported (Tr) observations. Same writers, same observer hooks.
4. In `FullWidthPair` the files carry explicit metadata: `session.json` schema `local-ccf-capture/2` (legacy stays `/1`), `capture_mode`, `local_full_width_weight: true`, the selected centres, and a statement of the weight normalization; `fft-config.json` records the actual `weight_x_norm` passed from `alignPatch` (the value that built the weight map). `configure` requires `weight_x_norm == pnx == 42` in this mode and fails otherwise, so a capture can never be labelled full-width while using the inherited normalization. The v2 schema also prevents silently mixing old-weight states with full-width states.
5. Runner guard (`MC_DIAG_LOCAL_CCF_DIR` scope check): the term refusing `experimental_local_full_width_weight` is removed. Everything else is unchanged and still refuses before any movie access: GPU, non-`--use_own`, B2, global half-gain, isotropic weight, DC arm not `both`, a different patch grid, iteration count, frame range, threads (j<=2), grouping, binning, interpolation, B factor, CCF downsample, skip_defect missing, tolerance. The weight flag itself remains refused without `--use_own` and with `--gpu` by its existing checks.
6. No change to arithmetic, weight formula, reference, peak, stopping, fitting, acceptance, defaults, publication, CUDA code or dependencies. Capture failures keep the existing behavior (error before the product queue; partial files retained; exclusive writes; 64 MiB cap). The distinction between the API argument and the actual C2R temporary is preserved by the existing inverse observer, used unchanged.

## Frozen test criteria (any relaxation must be recorded as an amendment)
Unit (`tests/test_local_ccf_capture.cpp`, extended; the existing assertions stay as they are):
- U1 Legacy: (62,47),(62,79) captured; (104,15) and (20,15) not captured; `session.json` bytes equal the pre-change bytes; a differential dump of session.json, patch.json, fft-config.json and the full array set of one legacy patch, built against the pre-change header and against the new header, is byte-identical (`diff -r`).
- U2 FullWidthPair: exactly (104,15),(62,79) captured; (62,47),(20,15),(62,15) not captured; both patches produce the same file set as a legacy patch for the same iteration count; `session.json` has schema `/2`, mode, selected centres and the normalization text; `fft-config.json` has `weight_x_norm` 42; no legacy-only coordinates appear.
- U3 failures: duplicate selected patch, missing selected patch at `finish()`, wrong extents, wrong centre/extent geometry, `weight_x_norm != 42` in FullWidthPair, overwrite of an existing file, and an existing root all throw; each failure test has a control that passes with the corrected input (no vacuous refusal).
- U4 existing behaviours preserved: observer bit-neutrality, preserved API buffer, two-thread disjoint frame records, rejected coupled offsets published as null with no uninitialized read, unclipped fallback, budget cap checked before open. Built with AddressSanitizer and UndefinedBehaviorSanitizer as an additional run.
CLI (`tests/test_local_ccf_capture_cli.py`, DC build only; no native movie):
- C1 legacy exact scope reaches the missing-input error (unchanged control).
- C2 full-width flag ON with the otherwise identical exact scope reaches the missing-input error (`absent.star`), the capture root is not created (the capture session is created after the movie is opened, so a missing input fails first).
- C3 with the flag ON, each of `--gpu 0`, `--experimental_local_b2`, `--j 3`, `--group_frames 2`, `--max_iter 6`, a different patch grid, and `MC_EXPERIMENT_CCF_DC_ARM` not `both` is refused before the missing-input error; the flag without `--use_own` is refused; root never created.
- C4 flag ON without `MC_DIAG_LOCAL_CCF_DIR`: capture-off path unchanged (reaches the missing-input error).
- Mutation checks (each must fail the named test, then be reverted): guard still refusing the flag (C2); FullWidthPair selecting (62,47) instead of (104,15) (U2); duplicate check removed (U3); `weight_x_norm` check removed (U3).
Scope of evidence: a local build is evidence of compilation and these checks only. It establishes nothing about native capture, neutrality of the new binary, or science; the two producer checks below stay UNRUN.

## Build and resources
Source change is built from an exact `git archive` of the commit: CPU, Release, DC hook (`-DMC_EXPERIMENT_CCF_DC=ON`), no CUDA, existing dependencies only, no installs, `-j2`, `OMP_NUM_THREADS=BLAS threads<=2`, scratch <=2 GB, memory <=4 GB, disk and occupancy preflight recorded. `MC_EXPERIMENT_CCF_DC_ARM` is unset except where a test requires it. All failed attempts are kept.
